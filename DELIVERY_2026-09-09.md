## What changed

**Summary tab (parts/p9b_summary.js, rewritten).** Four tabs exactly — Overview (default), Overnight, Incidents, Near misses — under one compact toolbar (participant, from/to, 7 days · 4 weeks · 12 weeks, Export, Manage data). One coverage line, e.g. `Tim · 12 Aug – 8 Sep 2026 · 26 rostered nights · 20 logged · 6 not recorded · 57 completed shifts, 36 with a note`. Default period = last 4 completed weeks ending yesterday; shifts still running or not started are shown as "not yet finished", never as not recorded. Overview: six compact metrics (falls, near misses, assisted transfers, incidents involving an emergency call, average recorded overnight assistance, nights with complete data), each with unit and denominator or "Not recorded"; then overnight bars per night (hatched = partial, dashed = not recorded, click/Enter opens the records behind the bar), falls and near misses per day/week, transfers per day/week plus care measures. Every chart has a "Show as a table" alternative and visible units, dates and sample size. Overnight: nights in scope / complete / partial / average (with n) / episodes; night-by-night bars; time-of-night timeline keyed by the night the shift started; support by activity; night table with Details. Incidents: reports, falls, involving emergency services, injuries recorded (+ not answered), time on the floor with its sample; incidents/falls over time; types; fall locations; injury answer; record table with Open. Near misses: count, documented shifts, equipment, during a transfer; over time; location; activity; what prevented harm; record table with Open.

**Metrics (parts/p9a_metrics.js, `metrics-v3`).** Event/source model: a structured record is the counted instance; a reviewed observation that repeats it is linked (`duplicate_of_record` / `duplicate_of`) and kept as a reference; unlinked look-alikes on the same date within 30 min are flagged, never merged. Accepted observations with no structured record count as their own event. Missing is not zero anywhere. Overnight: intervals merged before summing (`evMergeIntervals`); night keyed by start date (`evNightOf`); after-midnight events on the period's last night are fetched (to + 1) and counted; window length from the clock (`evBlockHours`, 7/8/9 h); awake-without-assistance only when the whole window is accounted for; wakes labelled as "before the final wake". Care: totals/per-day only over logs that answered; showers offered / done / declined / outcome not recorded; transfers from structured counts, with reviewed transfer observations counted only on days with no log. Incidents: injuries yes/no/unknown; "incidents involving an emergency call" (never a call count); minutes on the floor only where recorded; transfer = the worker's answer, `inferred` only for pre-question rows. Series: day buckets ≤ 35 days, ISO weeks beyond. Definitions in `EVIDENCE_METRICS.md` and embedded in the export appendix.

**Manage data (drawer).** Review queue (accept / edit / reject / "repeats another record…" / unlink; night shown for after-midnight items; "uncertain" badge on night-time clock times found in documents not marked as sleepover narratives), Sources (import file / paste text / review an in-app note; originals unchanged; exact duplicates refused by hash; text extracted locally; scans marked for manual entry), Checks, Versions (finalise = freeze; open a version renders only its stored dataset; legacy `metrics-v2` versions are labelled legacy and not re-rendered), Demonstration (an entirely synthetic participant, shifts and records from `evDemoDataset`).

**Candidate finder.** Uses shift context: on a sleepover narrative, times before the shift's morning end move to the next calendar day and only 22:00–07:00 times can be overnight assistance; daytime sentences stay daytime on their date; a day-shift narrative never produces overnight items. Explicit negation ("did not fall", "no injury") is respected and never inverted. No staffing is ever inferred from prose (`workers_involved` is always null).

**Export (analytics).** Overview always; optional Overnight / Incidents / Near misses detail; compact appendix (record ids, source index with content hashes, checks, definitions). First page = identity line, coverage line, six metrics, three charts. Renders from the dataset only (`viewSumDoc`), so a finalised version cannot pick up later sources. A4, "Page x of y" footer, repeating table headers, no cover page, no disclaimers, no prose findings. Sample: `DELIVERY_2026-09-09_demo_export.pdf` (synthetic, 11 pages).

**Removed (funding/2:1 concept).** "What support is requested", provider funding statements, proposed staffing, clinician-recommendation tiles, allocation/shortfall fields, "Six things this report keeps apart", generated findings paragraphs, repeated legal disclaimers, the "second person needed" and "beyond one worker" metrics and rows, the roster 2:1 checkbox, chip badge and legend entry (double-booking clashes and split shifts kept). Incident form: "Was a second person needed…" no longer asked (a historical yes is shown as a note on that report); Q17 injuries now requires an explicit Yes/No (no preselected No). Near-miss form: "beyond what one worker can safely manage" no longer asked. Record exports show the retired answers only where a historical value exists. Test 17 greps `p9a`, `p9b`, `p10`, `p7` for two-worker wording.

**Related corrections.** Overnight split: Mon 18:00–09:00 split at 03:00 now creates the second segment on Tuesday (browser via `evSplitSegmentDate`; database via migration 005's `ac_split_shift`, which also refuses a split outside the shift). Transactional saves and honest partial-failure messages kept. Worker-role protections untouched. All new controls have associated labels (0 unlabelled inputs on the Summary). Reviewer/uploader = the authenticated account (`sumMe()`: the session's worker row, or the admin's own row for the PIN-verified admin session) — no device-stored name. pdf.js upgraded from 3.11.174 (end-of-life; CVE-2024-4367) to 4.9.124 ES module with `isEvalSupported:false`; extraction verified with a text PDF (2 proposals) and an image-only PDF (needs manual entry). Evidence storage remains the admin-only `evidence/` prefix (migration 002, applied 2026-09-08). Demonstration mode is entirely synthetic (test 20 asserts no real name, address or id).

## Known limitations

- "Page x of y" relies on CSS `@page` margin boxes (Chromium 131+); Safari prints without the number.
- The live Tim period contains no accepted observations yet, so the timeline and by-activity sections show their empty states until sleep-log narratives are imported and reviewed.
- Historical care logs saved before 7 Sep 2026 cannot distinguish an unanswered box from 0; they are listed under Checks.
- Until migration 005 is applied: linking a repeat to a structured record uses the legacy self-link (handled by the metrics); the database still forces `shower_done` to false on old rows (the form now requires an answer); the DB split function still dates the second segment on the start day (the browser fallback uses the correct date, and the DB path is used only once 005 is live).
