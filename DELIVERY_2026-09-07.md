# Astar Care — UI and evidence rework: delivery note (2026-09-07)

Branch: `codex/astar-ui-evidence` · Baseline tag: `classic` (the app exactly as deployed on 2026-09-05)
**Production is NOT updated.** Nothing was deployed, no live database change was applied, no message was sent.

## Rollback (one word)

```
sh revert.sh all        # whole app back to classic
sh revert.sh worker | roster | admin | summary | design | notes | calendar   # one area only
sh revert.sh undo       # undo the last revert
```
Each makes a normal commit; nothing is lost. `git diff classic -- parts/` shows every change.

## 1. What changed, by approved area

### A. Consistent professional design
* One token system (`parts/p1_head.html`): page #F5F7FA, surfaces #FFFFFF, text #172B4D / #475569, borders #D5DDE5, accent #155E63, restrained ok/warn/error. System sans stack (Segoe UI first); the Fraunces web font and its two network requests are gone. Body 15.5px, inputs 16px, nothing below 12px and metadata generally 13px, titles 24–26px, tabular numerals on times and amounts, 6–10px radii, subtle shadows, no gradients.
* Browser zoom restored (`maximum-scale=1` removed). Reduced-motion honoured. Visible focus ring kept.
* Tags are no longer shouting pills; segmented controls read as tabs; status chips carry a symbol and words, never colour alone.

### B. Worker experience
* Home now leads with **the shift you are on or your next shift**: dates and times (sleepovers show both dates), participant, address, clock in/out, and a record-status row (shift note saved / missing / not yet due; care log; overnight summary; incident and near-miss counts). Generic shortcuts moved below as “For another shift”. `<main>`, `<nav>`, `aria-current`, real headings.
* Calendar tick and “missing notes” now mean a **Progress Note**; a mileage-only entry is no longer treated as the shift note (`shiftNotesForShift`).
* Dialogs have `role=dialog`, a labelled title, focus moved in on open and restored on close, Escape closes (except editors), Tab is trapped inside. Every icon-only button has a name (28 added).
* Structured forms (care log, overnight, incident fall block): participant’s real name instead of hardcoded “Tim”; **blank stays blank** (stored as null, shown as “not recorded”), 0 must be typed; the shower question is no longer pre-answered; the fall block no longer pre-answers “No” and asks for location, second-person and equipment when the answer is Yes. Until migration 002 is applied the database still rejects nulls: the app then stores 0 and tells the worker so in a warning toast.

### C. Admin screens
* Roster: chips now distinguish **covered / needs cover / 2:1 on purpose / clash (worker double-booked)**, and label parts of a split slot; a key sits under the grid. Handover (end = next start) is treated as normal, never as an overlap. The 2:1 flag needs migration 002 and appears only when the column exists.
* Roster time edits and splits are **atomic** through database functions (migration 002). Before the migration, the app falls back to step-by-step saves and, on failure, reports exactly which shift saved and which did not — it no longer claims success after a partial save.
* Inbox: “Clear” is now **Waive note** with a confirmation explaining that nothing is deleted; “Done” is **Mark as read**; “Mark resolved” is **Resolve message**; the outstanding-notes list explains itself and ignores mileage-only entries. Mobile layout no longer squashes rows.
* Pay and Team kept their functions with the new tokens.

### D. Summary tab (was “Reports”)
* Five views: **Overview, Overnight, Daytime support, Incidents and outcomes, Sources and checks**. Every figure is computed in `parts/p9a_metrics.js` (pure functions, unit-tested) from records fetched **server-side in pages of 1,000 for the whole period** — the app’s rolling cache and its fixed row limits are not used.
* Coverage is always “n of N (%)”: rostered vs documented shifts and nights. Missing records are gaps, never zeros; partial records count only for what they contain; quiet nights are kept.
* Overnight: one bar per rostered night for **direct worker assistance** inside 11pm–7am, dashed outline for nights without a record, the 2-hour NDIS line drawn against assistance only and labelled as a pricing fact; a time-of-night timeline built only from accepted observations; awake-without-assistance derived and shown separately; wake times averaged correctly across midnight.
* Daytime: care-log load with “recorded n of m” per measure and per-day over days-with-a-log; a task table from reviewed observations; the four staffing facts kept apart (two actually assisted / difficulty reported / clinician recommended / provider requesting).
* Incidents: chronology with careful language (time on the floor ≠ time waiting; offered-not-completed ≠ declined; missing ≠ no); possible duplicates flagged, never merged.
* “Six things kept apart” statements (records / provider reports / clinician / requested / funding / unknown) are editable, saved with the draft, printed under their own headings. No conclusion about funding, no tribunal prediction, no legal advice anywhere.
* **Limited import and review**: upload (original stored unchanged under `evidence/<participant>/`, SHA-256 duplicate detection), paste text, or review an in-app note. Text is extracted **locally in the browser** (PDF via pdf.js, Word via JSZip, plain text); scans are marked *needs OCR / manual*. Time-anchored sentences become **proposed** observations with the quoted sentence as the source reference; a person accepts as stated, edits, rejects (with a reason) or links as a duplicate. Only accepted, non-duplicate observations from non-excluded sources enter any figure. Training samples are excluded by marking the source.
* Report versions: draft (re-saveable) and **final** (frozen snapshot of dataset, statements, source and observation ids, reviewer, time; database trigger makes it immutable).
* Report document: A4, white, one accent, numbered sections, page numbers (“Page x of y”), repeating table headers, a footer with report identity, selectable text, source index and methodology. Sections: context and request; coverage and findings; overnight; daytime and proposed staffing; incidents; proposed schedule and gaps; methodology, reviewer, source index. Sample with synthetic data: `demo_report.pdf` (7 pages, labelled DEMONSTRATION).
* A **demonstration mode** (Sources and checks → last section) loads clearly labelled synthetic sources, proposals and a finalised version in memory so the review screens and the sample report can be seen. Nothing is saved.

### E. Permissions, reporting and integrity
* `migrations/001_worker_row_protection.sql`: workers could update their own `ac_workers` row including `is_admin` and `rates`; `ac_is_admin()` trusted that row. A BEFORE UPDATE trigger now rejects changes to admin status, rates, email, active and login link unless the caller is an admin; anon grants revoked. Verified: 7/7 checks in a rolled-back transaction.
* `migrations/002_evidence_and_roster_integrity.sql`: evidence tables (admin-only RLS), immutable finalised versions, atomic roster RPCs, 2:1 flag, nullable counts, evidence storage prefix restricted to admins. Verified: 8/8 checks in a rolled-back transaction.
* `migrations/003_chaser_ignores_mileage_only.sql`: the push chaser no longer treats a mileage entry as the shift note.

## 2. Shift-note template: unchanged — PASSED
* `tests/check_template.js` compares `NOTE_TEMPLATE` and `NOTE_HEADS` in the source against a baseline captured from the `classic` tag (SHA-256 `b9219053…`); it also asserts the editor still inserts the untouched constant. Result: PASS after every change.
* Runtime round-trip (read-only, run 2026-09-07 against the local build with live data): an existing 3,438-character Progress Note opened in the editor equals the stored body (PASS); the read view keeps all 29 non-empty lines in order (PASS); the export contains the note verbatim (PASS); a new note starts with NOTE_TEMPLATE byte-for-byte (PASS).
* Only presentation changed: the note box grows with the text (no box-inside-a-box scrolling), 16px type, label associations, a short hint above the box. No new questions, mandatory fields, draft storage, validation or rewriting. The pre-existing behaviour of stripping legacy `**` markers when a note is opened for editing was left exactly as it was (it is not new, and it is reported here).

## 5. Incomplete, limitations, assumptions
* The import/review workflow and report versions are built and exercised in demonstration mode but cannot store anything until migration 002 is applied. Statements typed on the Summary are kept on the device (localStorage) until then, with a visible note.
* No OCR. Scanned documents are stored and flagged for manual entry, as specified.
* Daylight-saving: overnight figures are block counts from the paper log, so they are unaffected; clock-time averages use the minutes-after-noon rule. Absolute timestamps in the database are UTC; all displayed dates are the device’s local time, assumed Australia/Melbourne (stated on every report).
* The 2-hour reference is cited to the NDIS Commission “Sleepover shifts” page (worker alert dated August 2026) and the NDIS Pricing Arrangements and Price Limits it references. I could not fetch the PAPL document text directly during this session (the NDIS site returned 403 to automated fetches); the citation is therefore to the Commission page and the PAPL by name. Confirm the PAPL edition before the report is sent.
* Pre-2026-09-07 care logs and overnight summaries stored blank answers as 0; they are listed under Sources and checks rather than altered.
* Incident-form questions 8, 13 and 17 keep their original “No” defaults (they belong to the provider’s official form); only the fall block added in September lost its defaults.
* Statuses on the report use “Draft” / “Final”. Author/reviewer identity comes from a name typed once per device.
